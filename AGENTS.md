# Rules for Codex / coding agents

Project: **Stateful AI Session Re-placement**. Resource/safety mechanics use Section III dated 2026-11-06 (including reachability supplement); the current optimization objective uses the original 2026-11-07 weighted Section III.E under `docs/model_spec/2026-11-07-weighted/`. Authority and user no-priority/causal overrides are indexed in `docs/model_spec/README.md`.

1. Read `docs/model_spec/开发建模注意.md`, `docs/model_spec/README.md` and the authoritative model files. Current research jointly minimizes average full-Turn E2E and resource Overhead: `ω1·D̄_E2E + ω2·(β_mig·V_mig + β_sh·A_shadow + β_HO·V_HO)`. The 2026-11-07 E revision supersedes the 2026-11-06 latency-only E objective and conflicting historical objective wording. Weights, conversion coefficients and unit scales remain unset: do not invent default weights, normalization or an aggregate score. Remove Session service priorities/preemption/old selectors and require causal observations. Document unresolved ambiguities rather than changing the model.
2. Implement only the requested stage. Current Poisson workload integration and explicitly enabled handover.enabled Actual Handover/Draining are implemented; default static and S3-A planned-only paths remain. Reuse immutable WorkloadPlan privately, shared seeded inputs, global finite cutoff and frozen extended current-only observations. Optional min_inter_move_interval_s controls accepted plans and actual switches. MigrationAdmissionGuard enforces one fixed-Source/Target lease per Session independently of Access Handover, without Copy/Cutover or automatic catchup. S3-A implements private on-demand arrival-relative Markov mobility plans and ordered PendingMove queues on the existing EventQueue (mobility phase 80), finite observation_end_s and end-of-Session cancellation. In planned-only mode Actual Access, Execution, KV and Token/Flow provenance are unchanged; opt-in S3-B changes Actual Access with protected serial Draining while Execution/KV/frozen provenance stay fixed. S3-C integration validation is complete; S3 freezes after this closing round. No future plans or horizon in OnlineObservation. Keep legacy S1-D/S2-C runtime stage labels without mobility; planned-only mobility reports S3-A and enabled actual Handover reports S3-B. S3-C is the integration acceptance stage. Current S2-C adds default unweighted Max-Min progressive filling for shared wired links on the existing Flow/byte kernel and EventQueue. NetworkTopology remains the unique static topology; reuse EdgeState. Remote Serving requires explicit allowed-pair membership, model deployment and both directed paths. Default MaxMinAllocator uses whole fixed paths, exact residuals and equal Flow weights. DisjointPathAllocator is only an explicitly injected historical guard. Reallocate after settling old Byte on start/end/cancel/pause/resume/supply; no empty/completed/cancelled/explicitpaused Flow consumes bandwidth. A producer-closed Flow with pending Byte remains eligible until drained. Wireless stays outside wired Max-Min. Record per-allocation Flow/Link loads and preserve one response Flow per Turn/path. Prompt wireless must finish before wired forwarding/GPU Ready. Each Turn response uses one persistent path-bound Flow, token Byte boundaries precede wireless FIFO. No actual KV Copy/Cutover or policy. S1 cleanup uses canonical core/resources/simulation/demos modules exclusively; removed root forwarding modules must not be restored. Formal serving retains Turn-level GPU slots/FCFS/Equal-Share, KV atomic commits/block/recovery, independent wireless FIFO, zero Idle and full E2E. Without topology keep fixed Access=Execution; explicit topology allows fixed remote Access/Execution without moving either. Reject every per-Turn Access config at loading; TurnPlan contains input/hidden output only. Session initial/current Access, Turn submitted_access_edge_id and frozen OutputToken provenance remain distinct. Runtime.deliver_token requires an explicit token_id; Turn results have no ambiguous access_edge_id alias. Turn.delivered remains the sole delivery prefix. Resolve retained unit boundaries at the same clock; never requeue continuously computing Turns per Token. Keep the useful low-level atomic GPU APIs and S0 lifecycle/safety validation. No H/L, preemption, old selector, actual KV Copy/Cutover/policies. See docs/ARCHITECTURE.md; stage audit reports are optional local history.
3. Keep simulator/environment mechanics separate from policies. Never let future session turns, future access changes, actual remaining outputs or future events leak into policy observations.
4. Report actual logical KV Copy Byte, materialized Shadow KV Byte·s and actual extra Handover response-forwarding Byte separately. Do not multiply logical Byte by path hops, count unmaterialized promises as Shadow, erase sunk cost on failure/cancel or add E2E waiting twice. Current S3 has no KV Copy/Shadow mechanism; report their actual zero overhead without claiming migration exists. Do not add penalties beyond the authorized weighted objective, hard budgets, a context reset, resident-session caps or idle/offload without approval.
5. Do not describe S0's single-user radio scheduler as the final wired Max-Min network scheduler or GPU Processor Sharing. S1-A GPU Processor Sharing is a separate implemented resource; S2-C wired Max-Min is implemented separately in network/max_min.py.
6. G1 is `mean_full_turn_e2e_s`, the mean over ALL planned legal Turns, defined only when every such Turn has a real full-delivery time (null for incomplete/empty workloads). Include legal zero-output completion. `mean_completed_full_turn_e2e_s` and completed-subset P95 are diagnostics, never substitutes for G1. Report completion, unfinished/unsubmitted counts, KVBlocked, censoring durations and reasons separately; never assign unfinished Turns zero delay, fabricate delivery or discard difficult workloads.
7. Don't claim tests passed until actually run, and report the exact commands and results.
8. Keep credentials, SSH config, joblib artifacts, model weights, private data and large runs out of Git. No external code copy without source/license checks.

9. Follow docs/REPOSITORY_FILES.md and the explicit release/server_files.txt / github_files.txt lists. Keep all generated runs, logs, stage audits and development plans local; never publish recursively. Preserve real test fixtures, especially docs/s1d_verification.json, which is an actual verifier input. New source files require whitelist review; new S3/S4/S5 results belong under runs/.

10. S0, S1, S2, S3-A Mobility, S3-B Handover and S3-C Integration are complete. Freeze S3 after this closing round; later changes require a demonstrated defect and the smallest necessary fix. S4 KV Live Migration is not yet designed or implemented; S5 Joint Re-placement has not started. Do not implement or prematurely design S4/S5 in S3 maintenance.
11. Preserve fixed regressions, independent Oracles and boundary assertions. Full unittest must also run at least 50 legal random scenarios by default, using a fresh Master Seed unless `SESSION_TEST_SEED` is set; `SESSION_TEST_CASES` defaults to 50, with an extended run of at least 500. Use local RNG and stable Seed derivation, print Master/Case Seeds and counts, retain failed config and replay command, and propagate failures. Never ignore exceptions, weaken legality or auto-change Seed to obtain PASS. Verify units, Token/KV/Byte conservation, deterministic ties, resource bounds, event progress, full E2E, mobility FIFO, protection and causal observations.
12. Tests must use isolated temporary directories and have no dependency on pre-existing `runs/`, outputs, historical logs, test order or a local environment. The module writing CLI output creates its parent directories. Clean-clone validation uses an independent temporary source copy without `.git`, `runs`, environments or caches; never remove user results to simulate a clean clone. Random-test PASS is not algorithm performance evidence; formal strategy comparisons share external workloads, mobility plans and common Seed sets.
