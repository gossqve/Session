> 版本：2026-11-05（依据本轮确认的最新要求）  
> 性质：**后续 Codex 开发与验收的强制执行规范**，不是覆盖 A–E 正式建模的替代文档。  
> 适用：S1-Foundation、S1-C/D/E、S2 Network、S3 Mobility、S4 KV Live Migration、S5 Joint Re-placement、S6 综合评估、S7 候选 PPO。  
> 当前约束：**本小论文删除高/低优先级及 GPU 抢占；在线系统不可读取未来工作负载。** 如旧文件与最新明确要求冲突，应记录并以本轮决议为准；其余机制以已确认的最新 A–E 建模文档为依据。

## 0. 核心原则（一句话）

**小场景验证 ≠ 简化系统模型。进入某一模块后，首先依据正式建模建立完整实体、状态、状态转移、资源约束和接口；再用简单参数和小场景验证；最后连接到真实的 Session/Turn 事件闭环。**

参数规模可先用手算值、后续以有依据的正式配置替换，但不得把正式实体简化为任务 ID 字符串、单个公式计算器或与主仿真隔离的演示程序，并宣称该模块已完成。

### 每个模块完成的五道门槛

1. **实体完整性**：正式建模所需的字段及关系具备唯一权威数据源；标记运行态、配置态和未来计划的边界。
2. **行为完整性**：事件触发、状态转移、结束/失败/暂停/恢复和资源释放真实发生，而不只是事后计算一个数字。
3. **建模一致性**：公式、约束、时间、计量单位、极限边界与最新权威文档对应；不得悄然恢复旧规则。
4. **系统集成性**：本模块最终与 Session/Turn 和完整 E2E 主执行链路联通，不能仅有单元演示。
5. **可验证性**：手算、正常、边界、阻塞/异常、守恒、确定性、无未来泄露与历史回归测试全部具备；输出审计对照表。

**验收记录必须包含**：`建模条款 → 数据字段 → 代码文件/接口 → 状态转移事件 → 测试用例 → 实际输出/差异`。缺项就不能称“整个模块已完成”。

## 1. 不可改变的系统目标与边界

- 场景：多 Area、多 Edge、预部署候选模型、Session 入场时选定 LLM 且此后固定、用户可移动、一个 Session 多轮 Turn、历史 KV 跨 Turn 保留。
- Access Edge `a_s(t)` 与真正持有**唯一权威 KV**并执行推理的 Execution Edge `y_s(t)` 是不同概念；移动只改变 Access，Execution 只有安全 Cutover 后才改变。
- 优化动作：**在线联合选择存活 Session 的目标 Execution 布局**，允许 No-op、单 Session 或多 Session 联合调整。不得提前读取未来 Access、Token、Turn 数、结果与迁移成败。
- 主指标：完整 Turn E2E，即合法回复最后一部分到达用户的时间减 Turn 提交时间。流式 Decode 与网络发送可能重叠，不能机械相加各阶段持续时间。
- 全量平均 E2E 只有同一外生工作负载的全部合法 Turn 都完成时才有定义；未完成、KVBlocked 和删失必须分别报告，不得将未完成记为 0、用完成子集冒充全量分母。
- KV 成本：实际逻辑 KV Copy Byte 与已物化 Shadow Byte·s 分别报告；不随意相加为目标或设硬预算。失败/取消已发生的迁移开销仍记账。
- 当前是**CPU 上执行的离散事件仿真**，不必加载真实 LLM、真实 GPU 或分配真实 KV Tensor；等效计算与字节状态必须有明确来源及单位。
- 本篇无 Idle / Host Offloading、无线调度、动态路由、真实 Continuous Batching；PPO 尚未实施，不能假设收益。

## 2. 本轮新增的两条硬规则

### 2.1 删除 Session 优先级与 GPU 抢占

- 从正式 `Session`/`Turn` schema、输入配置、合法性校验、在线 Observation、GPU 等待队列规则中删除 `priority=H/L` 及其依赖。
- GPU 名额限制保留，候选计算 Turn 采用**FCFS**；不存在 H/L 优先调度和一换一抢占。
- `EventQueue` 的 **事件排序 priority** 若只用于“同时间事件处理次序”，可以保留，但要改名/注释避免误读为 Session 服务优先级；严禁以其实现 H/L 调度。
- 旧 S0 配置含 `"priority": "L"`，旧 S0 校验要求 H/L。这是需要整改的兼容遗留，不是正式新模型。清理时同步审查旧测试和 README，禁止“为保测试通过而悄悄保留旧规则”。

### 2.2 不允许在线系统查看未来

明确分成至少两层：

1. **私有 WorkloadPlan / WorkloadDriver**：可为可复现性预生成 Session 到达、各 Turn 新输入/隐藏计划输出长度、Turn 级计划 Access、终止条件等；只有驱动器和离线评价器能看到完整计划。
2. **RuntimeState / OnlineObservation**：只公开已经到达的 Session、已知固定绑定模型、当前已揭示的输入、已经生成/交付的 Token、当前 Context/KV、当前 Access/Execution、当前资源/队列/链路、已经发生的事件及等待；不能含未来 Turn 列表、未来输出总长度、未来 Access、Session 剩余轮数和下一事件的真实信息。

- **重要区别**：当前提交的输入长度可以在请求实际提交时为其传输/处理所使用；本轮的未来**输出总量**仍必须对在线策略隐藏，Decode 由私有驱动器根据终止事件逐步揭示。
- Session 总轮数、未来移动序列可预生成用于 **离线生成/公平评估**，不允许调度策略看到，也不得把计划剩余工作量提前变成已经占用的 KV 或未来收益预测依据。
- 旧 S0 会在初始化时遍历所有未来 Turn，并预判整个未来 KV 容量和 Context；这是仅供旧手算 Smoke 的局限。**新正式运行路径必须改为事件时、逐 Token 原子容量/Context 检查**；优先在 Foundation/集成阶段清理这类提前查看。如果历史测试预期“构造器直接报错”与新在线语义冲突，记录原因并更新成对应的运行时异常/阻塞断言，不得仅删除测试。
- 必需的无泄露测试：构造两组负载，在时间 `t` 前所有已发生事件和输入完全相同、但 `t` 后的计划输出或移动/轮数不同；比较 `t` 时在线 Observation、合法动作输入及前缀资源决策必须完全一致。
- 建议策略仅接收经过显式构造的只读 Observation，而不持有 WorkloadPlan / Driver / 完整全局 config 的可遍历引用；增加自动化字段白名单及 `asdict`/序列化检查。

## 3. 基础实体必须按建模完整定义（S1-Foundation）

下表是**建议代码字段集与职责**；命名可与现有仓库风格一致，正式符号/具体参数以最新 A–E 模型为准。不得因为当下只有 1 Edge 就省略 Access/Execution 概念。

| 实体 / 数据层 | 当前阶段需要的内容 | 后续扩展点或边界 |
|---|---|---|
| `ModelSpec` | 模型 ID、结构参数 `L_m, H_KV, d_head, element_bytes`、原生 Context Window、每 Turn 输出上限、Prefill/Decode 的等效 work/token；由结构公式**派生** KV Byte/token | 模型部署兼容矩阵属于 Edge/环境；模型绑定入场后不变 |
| `SessionState` | `session_id`、固定 `model_id`、会话到达/生命周期、当前 Access/Execution、当前 Turn 标识、累计已提交 Context、权威 KV、当前状态和结束时间 | 不包含 H/L priority；不包含未来 Turn 列表 |
| `TurnState` | Session ID / 序号、已揭示的当前输入、Prefill 已提交 Token、Decode 已生成有效 Token、已交付 Token、提交/Ready/Start/接收时间、GPU 部分 work、等待与异常原因 | **未来计划输出长度不能作为可观察字段**；不误把 GPU 任务完成当完整 Turn 完成 |
| `EdgeSpec/State` | Edge ID、部署模型兼容关系、`C_e^GPU`（eq-work/s）、`L_e`（同时运行 Turn 名额）、`C_e^KV`（扣除固定模型权重等后的净 KV Byte）、计算运行集合/FCFS 队列/权威 KV 占用 | Area 归属、链路和 Target Shadow/承诺按 S2–S4 逐步接入，但同一 Edge 实体继续扩展 |
| `GPUComputeTask` | 真正的 `session_id+turn_id+phase+token/工作片段` 映射、Ready 和剩余等效 work、当前 GPU/Queue 状态 | 作为任务执行视图，不取代 Session/Turn 状态，也不自持未来输出总量 |
| `WorkloadPlan/Driver` | 完整预生成负载、Seed、私有输出终止与未来 Access 信息；按事件逐步揭示 | 与在线状态/策略对象**强隔离** |
| `OnlineObservation` | 当前可见的 Session/Edge/Queue 等快照（只读、白名单），不持有私有计划 | S5 PPO/Greedy 复用同一接口 |
| `Metrics/EventTrace` | 每事件时间、Session/Turn/Edge、各资源增减、完成/阻塞原因、Turn E2E、未完成数量 | 不能通过记录器反向暴露未来给策略 |

### 已冻结的基础公式/逻辑

- `b_m^KV = 2 * layers * num_kv_heads * head_dim * bytes_per_element`，单位 Byte/token；`K_s(t) = b_m^KV * N_s^ctx(t)`，同一 Session 各 Turn 的 Context 累计，不能每轮清零。
- Context 上限是**绑定模型的整个 Session 累计原生 Window**；单 Turn 最大新输出独立限制，达到该上限并不自动结束整个 Session。
- Input Prefill Token 与有效 Decode Token **实际计算完成并合法提交时**同步增长 Context/KV；未来计划 Token 不可提前变成 KV。
- `C_e^GPU`、`L_e`、`C_e^KV` 是三个独立量。运行 `n>0` 时，每运行任务 `C_e^GPU/n`；等待队列不能消耗算力。GPU Ready、排队、网络等待和 KVBlocked 分开记录。
- 同一 Session 只有一个当前活动 Turn；上一 Turn 的完整输出实际到达用户时，下一 Turn 立即提交（无额外 Idle）。
- 真实 Session 结束后释放其**全部权威 KV**；不提前释放、不冒用 Shadow。
- 不新增独立的“Session 最大接纳数量”硬上限，除非最新正式建模有明确且仍有效的依据；不要从早期材料恢复已撤销规则。

### S1-C：KV Context + 净显存 + KVBlocked 完整机制

建立与 Session/Edge 正式实体相连的 KV 管理器，而非仅有可加减的独立计数器。工作包括：

- 实际 Token 完成时原子提交 Context 与该 Session 权威 KV；不允许部分写入或预支未来。
- 按模型结构计算不同 Session 的真实 Byte/token；Edge 占用 = 其驻留 Session 权威 KV 总量（S4 时再并入有效的 Target Shadow 承诺）。
- 运行时检查原生 Context Window、单 Turn 最大输出、Edge 净显存；严格区分 `ContextLimit` 与 `KVBlocked`，不伪造成功、不临时扩容。
- `KVBlocked` 保存已完成工作、已提交 KV 和待提交 Token 边界；释放 GPU 名额；真实容量改变时按合法条件重试，不能用 `cancel` 冒充暂停；不保证所有阻塞都必然解开。
- Session 自然结束释放全部权威 KV，Edge 和 Session 汇总守恒；S4 迁移的 Shadow/承诺接口应当预留，但不能伪称 S1 已实现迁移。
- 用多 Session 共用 Edge、不同模型 KV 大小、恰好容量边界、容量不足、资源释放与恢复、上下文到达上限、重复事件等情况测试。

### S1-D：多 Session 多 Turn 完整 E2E 运行闭环

把 S0 Turn 生命周期接入 S1-A/B/C 的统一主事件引擎：当前输入合法上传 → GPU Ready/FCFS → Prefill/Decode 与等权共享 → Token/KV 同步提交 → 输出流式交付 → Turn 完整接收 → 立即下一 Turn 或 Session 自然结束。至少两个不同绑定模型的 Session 同时活跃，且至少一个有多 Turn。

验证：每一个实际 GPUTask 对应唯一 Session/Turn/阶段；不同 Session 的 Context/KV 独立；GPU 队列等待计入 Turn E2E；已生成但未下行 Token 不算完成；无线流水与 GPU 并行；阻塞/恢复不重复做计算；无未来泄漏；完成率及未完成情况正确。

### S1-E：完整建模一致性验收与一次提交

产生：字段—建模—事件—测试对照表、手算轨迹、全部回归、未完成场景记录、配置/Seed/Commit 记录、当前限制；实际通过后再由用户在服务器统一 Git Commit/Push。不得把组件测试通过冒充整体系统完工。

| **S6 参数与正式评估** | 在**已完整实现**的环境上定值三 Area/多 Edge 配置、模型参数、Session 到达与长度分布、移动强度、资源瓶颈、Seed、评估指标及场景矩阵 | 多 Seed 可复现、参数有出处和单位、同工作负载公平比较；不得用 S6 才补此前漏掉的正式机制 |
| **S7 PPO（候选）** | 确定状态/动作/合法约束与时延反馈、独立 Train/DEV/TEST；在冻结 S6 环境训练与对照；迁移开销独立分析 | 收敛曲线和方差、对照与消融、无未来泄漏、统计可信。若 PPO 不优于基线，不能虚构改善 |

**安排准则**：规则/类型从第一阶段完整明确；该阶段的运行机制和与 Session/Turn 的对接必须在本阶段结束前实现；仅参数数值、场景规模和算法超参数允许之后再定。特殊情况下不得一口气赶完全部模块，应拆成可验收的子任务，但**不可以把子任务测试当作模块终验收**。

## 6. 每次给 Codex 的开发流程和禁令

### 工具与目录

- Codex Desktop 使用 **Windows Local 模式**，唯一主动编辑位置：`D:\software\yxyWork\gitcode\Session`。
- VS Code Remote-SSH 负责服务器可视化、实验运行和最终 Git 版本管理，服务器正式目录：`/mnt/data2/users/yxy/llmwork/session`。
- 本地 Codex 不执行 SSH/SCP、Commit、Push、Pull、Reset，也不修改远程或全局配置；每次完成给出实际修改文件清单，用户再按 `scp -P 54004` 上传。
- 同一阶段不得在 D 盘和服务器端**同时独立修改同一份源码**，避免 SCP 覆盖。服务器未提交的 S1-A/B 不能使用会丢失更改的 `git reset --hard`。
- 上传后在 VS Code 服务器运行全量测试、演示、S0 基线回归；当前用户要求**S1 全部验收后才做一次服务器 Git Commit/Push**。上传同步注意文件删除/重命名不能靠 SCP 自动清理。
- 不提交 `runs/`、`.venv/`、缓存、密钥、密码、Tokens 或大模型权重；公开仓库只提交确认可公开的源码、配置、测试及适宜公开的文档。

### Codex 编码前

1. 读取 `AGENTS.md`、`README.md`、相关源码、测试、配置和本开发规范。
2. 列出本轮所涉正式建模条款，核对最新 A–E 文档；源材料缺项或版本冲突要明确标注，不编造功能/阈值。
3. 逐条列出新建实体、与已有模块的关系、唯一权威字段、事件/状态转移、不变量、边界情况。
4. 检查是否已经存在可复用的 EventQueue、GPU 和 GPUQueue，不造并行同义模块。

### Codex 编码后

1. 实际运行原有+新增单元测试、集成测试与可手算演示；输出真实数量和日志。
2. 审计序列化出的 OnlineObservation 与资源调度器入参，证明无未来泄漏。
3. 对比 S0 的正常基线结果（2/2、0.7s、Context=6、KV peak=24、结束释放后 0），如内部测试语义因规则修订需要改变，要解释原因，不能静默吞掉。
4. 输出「新增/修改/删除文件」清单、测试输出、手算检查、没有实现的功能清单、服务器上传路径和命令、最终合格条件。
5. **不谎称代码已在服务器运行、不谎称已经 Commit、Push、不谎称已完成尚未与 Session 集成的机制。**
